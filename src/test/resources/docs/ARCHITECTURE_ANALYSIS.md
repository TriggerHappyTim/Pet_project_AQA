## 2. Дублирование стратегий

### 2.1 Проблема: Два пакета для стратегий

**Текущая ситуация:**
- `com.bft.config.*` - стратегии конфигурации (5 файлов)
- `com.bft.strategy.*` - стратегии выполнения (8 файлов)

### 2.2 Детальный анализ

#### TestStrategyType vs ExecutionStrategyType

| Пакет | Enum | Назначение | Использование |
|-------|------|------------|---------------|
| `config` | `TestStrategyType` | Общие типы тестов (UI, API, MOBILE) | ✅ `TestConfiguration.java`, `TestConfigurationTest.java` |
| `strategy` | `ExecutionStrategyType` | Конкретные стратегии выполнения | ✅ `CryptoProCertificateTest.java`, `ExampleTest.java` |

**Вывод:** Это **НЕ дублирование** - разные уровни абстракции:
- `TestStrategyType` - высокий уровень (тип теста)
- `ExecutionStrategyType` - низкий уровень (конкретная стратегия выполнения)

#### ApiTestStrategy vs ApiTestExecutionStrategy

| Пакет | Класс | Назначение | Использование |
|-------|-------|------------|---------------|
| `config` | `ApiTestStrategy` | Конфигурация окружения для API тестов | ✅ Используется в `TestConfiguration` |
| `strategy` | `ApiTestExecutionStrategy` | Выполнение конкретного API запроса | ✅ Используется в тестах |

**Вывод:** Это **НЕ дублирование** - разные ответственности:
- `ApiTestStrategy` - настройка окружения (Selenide, переменные окружения)
- `ApiTestExecutionStrategy` - выполнение HTTP запросов (RestAssured)

#### BaseTestStrategy vs BaseTestExecutionStrategy

| Пакет | Класс | Назначение | Использование |
|-------|-------|------------|---------------|
| `config` | `BaseTestStrategy` | Базовый класс для стратегий конфигурации | ✅ Родитель для `ApiTestStrategy`, `UITestStrategy` |
| `strategy` | `BaseTestExecutionStrategy` | Базовый класс для стратегий выполнения | ✅ Родитель для `ApiTestExecutionStrategy` |

**Вывод:** Это **НЕ дублирование** - разные иерархии наследования.

### 2.3 Рекомендации по стратегиям

**Статус:** ✅ **Архитектура корректна** - нет дублирования.

**Объяснение:**
- `config/` - отвечает за **конфигурацию окружения** (браузеры, Selenide, переменные окружения)
- `strategy/` - отвечает за **выполнение тестов** (HTTP запросы, валидация, подготовка данных)

**Рекомендация:** Оставить как есть. Это правильное разделение ответственности (Separation of Concerns).
