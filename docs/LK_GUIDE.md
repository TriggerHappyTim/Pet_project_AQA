# ЛК: конвенции и масштабирование

Проект рассчитан на **~9 личных кабинетов (ЛК)**. Сейчас автоматизированы два,
в фокусе — ЛК Страхователя (UI).

## Текущие ЛК

| ЛК | Тег | Пакет с тестами | UIType (test / uat) | Статус |
|---|---|---|---|---|
| ЛК Страхователя | `lk-insurer` | `com.bft.LK_Insurence` (27 классов) | `EVS_TEST_LKS` / `EVS_UAT_LKS` | активная разработка (UI) |
| ЛК Архивной организации | `lk-archive` | `com.bft.LK_Archive` (ArchivesTest) | `EVS_TEST_LKA` / `EVS_UAT_LKA` | базовое покрытие |
| … ещё ~7 ЛК | `lk-<slug>` | `com.bft.lk.<slug>` (для новых) | добавить константы в `UIType` | план |

## Правила

1. **Каждый ЛК имеет тег `lk-<slug>`** на уровне класса. Это основной способ
   селективного запуска и CI-матрицы (вместо хардкода списков тестов).
2. **Ядро не знает про конкретные ЛК.** Всё ЛК-специфичное — в пакете этого ЛК.
   Общие компоненты/шаги — в `ui/`, `steps/`, `pw/`, `test/helpers/`.
3. **Не копипастим сценарии между ЛК.** Общий сценарий параметризуется
   (`@ParameterizedTest` + `DataProvider`), различия — через конфиг ЛК.
4. **URL и учётки** — через `UIType` и `TestUsers`/`CredentialManager`, без хардкода в тестах.
5. **Данные** — уникальные на тест (префикс ЛК + timestamp/uuid), с очисткой.

## Запуск по ЛК

```bash
# все smoke-тесты ЛК Страхователя
mvn -B test -Dgroups="lk-insurer & smoke"

# только UI
mvn -B test -Dgroups="lk-insurer & web"

# регресс конкретного ЛК
mvn -B test -Dgroups="lk-insurer & regress"

# всё по ЛК (без smoke-фильтра)
mvn -B test -Dgroups="lk-insurer"
```

## Чек-лист: новый ЛК за один день

1. **Тег**: придумать `lk-<slug>` (латиница, kebab-case), зафиксировать в этой таблице.
2. **UIType**: добавить `EVS_TEST_<LK>` и `EVS_UAT_<LK>` (если ещё нет).
3. **Пользователи**: добавить записи в `TestUsers` (или использовать существующие с префиксом).
4. **Пакет**: `src/test/java/com/bft/lk/<slug>/` для новых ЛК.
5. **Первый smoke**: 1–2 ключевых сценария, класс с `@Tag("lk-<slug>")` + `@Tag("smoke")` + `@Tag("web")`.
6. **Локальный прогон**: `mvn test -Dgroups="lk-<slug> & smoke"` — зелёный.
7. **CI**: добавить ЛК в матрицу запусков (когда включим матрицу) или использовать
   параметр `-Dgroups` в web-пайплайне.
8. **Документация**: обновить таблицу выше + кратко описать специфику ЛК.

## Что уже готово для масштабирования

- Теги `lk-*` на всех существующих тест-классах.
- Мульти-пользовательская модель (`TestUsers`, `MULTI_USER_GUIDE.md`).
- Изоляция браузерной сессии на каждый тест (`UITestBase` → `PwSession`).
- Билдеры данных (`com.bft.testdata.*`) и мониторинг флейков (`FlakyTestDetector`).

## Следующие шаги (когда ЛК станет больше)

- CI-матрица по ЛК: smoke каждого ЛК отдельной job (ЛК Страхователя — блокирующая).
- Отчётность Allure с разбивкой по ЛК (Epic/Feature = ЛК).
- CODEOWNERS по пакетам ЛК при росте команды.
- Переезд `LK_Insurence`/`LK_Archive` в `lk/insurer`/`lk/archive` (отдельным шагом, без спешки).
